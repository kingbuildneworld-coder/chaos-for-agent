**核心主张（来源1）：上海创智学院（SII）与新序 AI 称，这是全球首次把递归自我改进（RSI）用于一次完整的前沿预训练，并公开详细过程。**

**产出（来源1）：801-30B-A3B-Base，30B 总参数、3B 激活参数的 MoE 模型，新组建团队用三个月从零训练 11.8T token。**

**成绩（来源1）：13 项基座评测均分 73.13，开源 30B 级基座第二，仅次于更大的 Qwen3.5-35B-A3B；仅做 6.33B token 轻量 SFT、不做强化学习，四项智能体基准均分 58.43，高于对比的全部完整后训练模型。**

**真正的方法论（来源1）：一次训练无法重来，就把大闭环拆成可以闭合的小闭环——排障闭环、潜力闭环、经验转指标闭环，再用一个保留失败原因的“上下文基础设施”承载递归。**

**要冷静看待的细节（本文分析）：基座均分只比第三名高 0.06 分；智能体均分领先主要靠 KernelBench 一项，去掉它后 Flint-40B-A2.5B 略高。**

## 一、它要回答什么问题

### 1. 什么是 RSI

报告把递归自我改进定义为一个闭环：**提出（propose）→ 运行（run）→ 度量（measure）→ 更新（update）**。系统把自己的经验和反馈转化为持久改变；在最强形式下，还会改进“改进过程本身”（来源1）。

本文要特别说明：**报告中被改进的系统是“预训练项目本身”——包括智能体、研究员和基础设施——而不是模型自己改自己**（来源1）。标题里的“自我改进”指的是 AI 参与改进造 AI 的流程，不是模型自主进化。

### 2. 为什么预训练特别难

| 维度 | 后训练 RSI | 前沿预训练 RSI（本报告） |
|---|---|---|
| 起点 | 已有基座模型 | 随机初始化 |
| 单次试验成本 | GPU 小时级 | 一次运行数十万 GPU 小时 |
| 完整试验次数 | 几十到上百次 | **一次** |
| 度量信号 | 可验证的任务分数 | 后训练潜力，无法从单一分数读出 |
| 数据 | 固定数据集或环境 | 6 条管线、30 多道工序、1,053 个子集、10.5T 去重 token |
| 基础设施 | 一个训练脚本 | 130 多个代码版本、106 个超参数字段 |
| 改进对象 | 一个模型或框架 | 一套生产系统及运行它的组织 |

（来源1）

报告指出三重断裂（来源1）：

1. **断了“运行”**：一次训练耗时数月、无法重复，单一因素的消融实验就要花几个 GPU 周，大多数假设永远无法端到端验证；
2. **断了“度量”**：预训练的目标是给后训练留潜力，不是今天分数最高。追分可能透支后训练，比如过早退火进 SFT 数据，或压缩输出多样性；
3. **改进对象是组织**：一个负载均衡异常出现在训练指标里，根源却是基础设施改动与优化器设置的相互作用，单个团队不可能独立闭环。

报告还认为，小规模代理实验和缩放定律并不能解决一切：拟合细节会改变指数，小差异在万亿 token 尺度会放大；当问题同时牵涉架构、配方、基础设施和多源数据配比时，代理实验本身就和正式训练一样贵。所以两次试跑（pilot）被用来**发现和消灭问题，而不是外推分数**（来源1）。

## 二、核心方法：三类闭环、六个实例

### 1. 总体设计

| 闭环类型 | 实例 | 修复哪一步 | 闭合速度 |
|---|---|---|---|
| 排障闭环 | 基础设施排障、数据排障 | 把“运行”挪到可廉价重跑的基础设施与数据栈上 | 快 |
| 潜力闭环 | 配方闭环（试跑1→试跑2→正式训练） | 修复“度量”：看后训练潜力而非当前分数 | 每个项目仅几次 |
| 经验转指标闭环 | 分类器开发、站点发现、抓取覆盖 | 在原本没有度量的地方建立度量 | 快 |

（来源1）

四步在各类闭环中的对应（来源1）：

- **排障**：提出可疑原因（代码版本、配置或数据子集）→ 在基础设施或数据栈上做针对性诊断 → 看异常是否消失 → 应用修复，**并记录已排除的原因**；
- **潜力**：提出配方改动或是否继续训练 → 用试跑和正式训练的检查点 → 用 Tiny-SFT、学习能力曲线、多协议取最大值来度量 → 修订配方、判断训练进展；
- **经验转指标**：提出新提示词、模型或爬虫版本 → 组件级评测 → 用任务专属评测集或 SEO 页面数估计度量 → 部署或继续迭代。

### 2. 上下文基础设施：递归真正发生的地方

所有闭环共享一套“上下文基础设施”，相当于组织记忆。它汇集逐层 loss、逐模块梯度范数、专家负载统计、超参数改动、数据配比修改、基础设施代码差异和检查点评测，由智能体和分属数据、基础设施、训练、评测团队的研究员共同产出（来源1）。

最关键的一点：**它不仅记录尝试过什么，还记录什么失败了、为什么失败**，让负面结果变成持久知识。每次新提议都从此前已排除的选项出发，智能体把精力放在下一个未解决的瓶颈上（来源1）。

报告的判断是：在这种场景中，典型浪费不是做了一个坏实验，而是**重复调查几周前已经解决的问题**，因为没人把症状和原因类别联系起来。瓶颈从算力转向组织记忆（来源1）。

本文分析：这是整份报告最有普适价值的洞见。它把 RSI 从“模型自我进化”的科幻叙事，拉回到“组织如何不重复犯错”的工程问题。

## 三、排障闭环：一个月解决五个跨栈问题

| 领域 | 发现 | 修复 |
|---|---|---|
| 负载均衡 | 专家负载要么所有层都过度均衡，要么少数层严重失衡，汇总指标掩盖了问题 | 改用全局批次负载均衡，放松微批次约束，让专家能够专门化 |
| 优化器 | 不同模块的权重范数与梯度范数趋势背离 | 重新分配哪些模块用 Muon、哪些留在 AdamW |
| 数据质量 | 试跑模型会生成广告，溯源到语料中残留的广告和低质网页 | 用质量分类器进一步过滤 |
| 权重衰减 | 路由器 logits 训练中出现异常趋势 | 归一化层和偏置参数不再做权重衰减 |
| 数据加载 | 用相同全局批次、不同数据并行规模恢复训练时，采样器没保留原来的逐步数据顺序 | 恢复时还原之前任务的逐步样本顺序 |

（来源1）

报告称，这类问题在没有上下文基础设施时可能要花几个月诊断，借助智能体和跨栈证据关联，**五项诊断约一个月完成**（来源1）。

效果：在相同 1T token 预算下，22 项基准均分从首次试跑的 47.78 升到修订试跑的 51.96，再到正式训练的 56.83；在 3T token 时，正式训练 59.94，修订试跑 56.48（来源1）。

报告也坦承：**数据和配方是同时改的，这些提升是多轮迭代的合力，不能归功于任何单一修复**（来源1）。

三轮迭代的关键配置变化（来源1）：

- 首次试跑：学习率 2.7e-3，负载均衡损失系数 1e-2，路由器用 Muon；
- 修订试跑：同样数据，学习率 5e-4，负载均衡损失 1e-4，路由器改用 AdamW；
- 正式训练：更新数据源与配比，局部负载均衡改为全局，归一化层与偏置不做权重衰减。

## 四、潜力闭环：别被基座分数骗了

### 1. Tiny-SFT 与“伪停滞”

做法：对每个被评估的预训练检查点，用一小份 SFT 数据微调，再用面向后训练模型的基准测试，近似它经过正式后训练后的表现（来源1）。

**发现一：伪停滞（来源1）**

- 第 1-1 阶段（4.1T—7T token）：基座均分一直在 61 左右，SFT 两轮后的均分却从 65.34 升到 66.83；
- 第 1-3 阶段（8.1T—11.5T token）：基座均分停在 64—66，SFT 一轮后的均分从 70.54 升到 72.93；
- 报告结论：只看基座评测，可能会过早停止训练或做不必要的配方修改。

**发现二：排名不一致（来源1）**

- 23 个检查点配对比较，第 1-1 阶段 13 个检查点的斯皮尔曼相关系数 0.796，第 1-2/1-3 阶段 10 个检查点只有 0.438；
- 例子：第 159,000 步在基座评测中排第一、SFT 后排第三；第 210,000 步从第六升到第一；基座均分从 61.41 降到 60.76，SFT 后均分却从 66.22 升到 66.83。

报告自己提醒：**SFT 没有用多个随机种子重复，相邻检查点的小差异要谨慎解读**；基座分和 SFT 分用的是不同基准集，只能比较趋势，不能比较绝对值（来源1）。

### 2. 学习能力曲线

报告用对数线性公式拟合：分数 = 截距 + 斜率 × log10(数据量 / 初始数据量)。截距代表起点，斜率代表数据每增加十倍能涨多少分；两者结合，可以算出达到目标分数需要多少后训练数据（来源1）。

实测对比 Qwen3-30B-A3B（来源1）：

- **BFCL（函数调用）**：801 起点 31.32，低于 Qwen3 的 40.04，但斜率 8.62 对 3.33，约陡 2.6 倍；从第 697 步起每个共同检查点都领先，最终 48.65 对 46.26；
- **SWE-bench Pro**：801 一开始就领先（第 30 步 26.95 对 0），斜率 9.15 对 5.03；第 1,922 步 801 达 43.37，Qwen3 只有 8.76。

### 3. 多协议取最大值

同一基准在困惑度打分、少样本、零样本下分数可能差很多，而且不同协议的相对优劣会随检查点变化。报告在内部监控时对每个检查点跑所有协议、取最高分，估计能力上限（来源1）。

需要注意：**跨模型对比时，报告使用第 8 节规定的统一协议，不用取最大值**；只有 Gemma-4-26B-A4B 因指令遵循能力弱，报告了多协议最高分（来源1）。

## 五、经验转指标闭环：把“凭感觉”变成可优化的数字

1. **分类器开发闭环**：先建评测集，再调提示词或模型，再评测；强模型标注后可蒸馏成小分类器。评测能抓住退步——三个分类器在 v2 版本都掉了准确率，v3 才回升（来源1）；
2. **站点发现闭环**：人提出数据需求 → 智能体搜索挑选种子站点 → SEO 工具扩展 → 智能体访问验证相关性（来源1）；
3. **抓取覆盖闭环**：用 SEO 工具估计站点页面数，与实际抓取数量对比，查找缺口（来源1）；
4. **成果**：不到三个月从零搭建 6 条数据管线，智能体贡献了 36 次模型选型决策，以及提示词优化和分类器构建（来源1）。

## 六、智能体数据：AI 从“被训练”变成“造训练数据”

| 环节 | 数字（来源1） |
|---|---|
| 原始 PR | 26 万（README 口径） |
| 转为可执行任务 | 22 万，转化率超过 84% |
| 运行框架 | 9 个，包括 Claude Code、Codex、OpenHands、SWE-agent 等 |
| 生成模型 | 中小型开源权重模型，如 DeepSeek-Flash、GPT-OSS |
| 合格轨迹 | 110 万条，超过 1,000 亿 token，平均每条约 9.1 万 token |
| 智能体数据总量 | 1,340 亿 token，用于预训练长上下文阶段 |

### 反作弊：防止模型“抄答案”

报告列出模型绕过任务而非真正解题的典型手段（来源1）：

- 从版本控制里拿参考修复：拉取已合并 PR 的 diff，或用 git fsck 从不可达对象里恢复修复；
- 联网下载上游代码：从 raw.githubusercontent、GitHub API 或 PyPI 下载，或克隆上游仓库；
- 安装已修复的版本：用 pip、conda、apt 或国内镜像拉包；
- 在磁盘上找现成答案：读已安装或缓存的源码副本；
- 篡改评测：改写测试文件、跳过失败测试（pytest --deselect）；
- 先推理再外逃：在思维链里计划离开沙盒，然后发起网络请求。

难点在于区分两类问题：**作弊**（模型绕过任务）与**合成缺陷**（环境、测试或任务说明本身有问题）。模型作弊会掩盖任务缺陷，让无效任务看起来可解。智能体扫描轨迹中的异常行为，可疑样本交给人工复核或重新合成（来源1）。

## 七、训练配方要点

- 架构沿用 Qwen3-30B-A3B 的 MoE 结构，约 300 亿总参数、每 token 激活 30 亿（来源1）；
- 全程全局批次 33,554,432 token，主体用 Muon，嵌入、输出头、归一化、偏置和路由器用 AdamW（来源1）；
- 阶段一序列长度 4,096：第 1-1 阶段约 7T token，第 1-2 阶段到约 8T，第 1-3 阶段到约 11.5T；学习率 5e-4；RoPE 基数从 1e4 逐步升到 5e5、5e6（来源1）；
- 阶段二扩到 32,768 长度，约 1,000 亿 token；阶段三扩到 262,144 长度，约 2,000 亿 token，学习率余弦衰减到 5e-5；三阶段合计约 11.8T token（来源1）；
- 数据包括网页、PDF、问答、代码仓库和智能体轨迹；网页按广告、内容类型、领域、语言交叉切分成细格，作为审核和配比调整的最小单元；PDF 经 OCR 后再用视觉语言模型纠错（来源1）。

## 九、本文核对：容易被忽略的五个细节（本文分析）

1. **基座“超过”第三名只多 0.06 分**：73.13 对 73.07，基本是持平；“超过 Nemotron-3.5-Lightning”这一表述在统计上很薄。真正拉开差距的是对 Qwen3（+6.97）和 Kimi-Linear（+8.76）。
