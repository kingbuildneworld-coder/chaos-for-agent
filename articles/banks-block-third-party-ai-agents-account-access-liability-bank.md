# 把Agent挡在门外

**从 10 月美国四大行到 11 月英国五大行，多家银行集体封锁或限制第三方 AI Agent 登录客户账户。**

**银行的真实顾虑不是反 AI，而是无法验证的委托：软件用客户密码登录、以客户名义行事，却证明不了自己被授权做什么。**

**在责任归属没有定论之前，银行选择先把 Agent 挡在门外，部分禁止其在客户未参与时代为交易。**

**也有机构通过用户协议把风险甩给客户，或自建授权层把自己变成 Agent 的必经收费站。**

**开放银行原本为第三方接入设计的框架，在自主 Agent 面前出现了错配，监管正在重建准入与问责的边界。**

## 一、一场跨大西洋的集体封锁

1. **美国先行**：10 月 13 日至 20 日，摩根大通、嘉信理财、花旗和富国银行等陆续采取行动，封锁或通过合同重新分配第三方 Agent 的风险。
2. **英国跟进**：据英国《电讯报》11 月 8 日报道，HSBC、Barclays、Lloyds、NatWest 和 Nationwide 五家银行已着手阻止 Agent 进入客户账户。
3. **具体措施**：部分银行明确禁止 Agent 在客户未直接参与的情况下代其完成交易，也有机构限制 Agent 对消费者存款的访问。
4. **预防性动作**：这些措施大多是预防性的，目前没有证据显示 Agent 已经实际访问英国账户，有银行明确表示尚未发现此类活动。
5. **留有例外**：并非一刀切，花旗等机构仍允许部分经客户授权的只读数据访问，被禁止的是无法核验的登录和交易动作。

## 二、银行真正害怕的：无法验证的委托

1. **一个反常的会话**：从银行系统看，登录来自正确的设备指纹和密码，多因素认证码也准时到达，一切看似正常。
2. **露出马脚的行为**：随后这个客户在几秒内读完每个页面、迅速打开转账界面，操作节奏完全不像人类，银行却无法断定屏幕背后是人还是 Agent。
3. **问题的本质**：银行禁止的不是 AI 本身，而是不可验证的委托——软件拿着客户的凭证、以客户名义行动，却无法证明客户究竟让它做了什么。
4. **传统风控失灵**：密码、设备指纹和多因素认证只能证明登录这一动作，无法证明后续一系列操作是否仍在客户的真实意愿之内。
5. **检测困境**：当 Agent 直接控制客户设备的鼠标和触屏时，银行在技术上很难识别，这正是 UK Finance 等机构反复强调的难点。

## 三、三种应对策略：封锁、甩责、建收费站

1. **技术封锁**：以花旗、美银和英国五大行为代表，直接禁止 Agent 登录或代为交易，在规则明确之前维持账户的封闭性。
2. **合同甩责**：以富国银行为例，其用户协议新增条款定义第三方 AI Agent，明确使用 Agent 风险自担，Agent 发起的所有交易都视为客户已授权。
3. **自建收费站**：一些机构转而开发授权层和相关协议，控制 Agent 权限、验证人工批准，把自己变成 Agent 交易绕不开的强制检查站。
4. **逻辑各不相同**：封锁是先排除风险，甩责是把责任推回客户，收费站则是在接纳 Agent 的同时保留对数据和费用的控制权。
5. **共同的底线**：无论哪种策略，银行都不愿在没有明确授权和责任安排的情况下，为 Agent 的自主行为兜底。

## 四、责任真空：出错到底谁赔

1. **未授权支付规则**：现有规则保护未授权情形下的客户，部署 Agent 的受监管机构仍需对其交付的结果负责，包括消费者义务下的责任。
2. **责任链条断裂**：但当 Agent 用客户自己的密码登录、操作又被协议视为已授权时，客户、银行和 Agent 提供商之间的责任变得模糊。
3. **合同分配责任**：在法律明确之前，Agent 提供商、数据方和银行之间主要靠合同条款来分配责任，博弈空间很大。
4. **银行的担忧**：它们担心 Agent 错误管理客户资金，而在身份和授权无法核验的情况下，最终赔付责任可能落到自己头上。
5. **留痕成为关键**：要打破责任真空，就必须为每一笔 Agent 操作保留可核验的授权记录，证明指令的来源、范围和客户同意。

## 五、开放银行框架为什么失灵

1. **开放银行的设计**：它允许客户在授权下，把账户数据安全共享给受监管的第三方提供商，并指示其执行支付。
2. **明确的主体**：传统框架里的第三方提供商是持牌、可识别、可追责的机构，责任边界清晰。
3. **Agent 的错位**：自主 Agent 不是传统意义上的持牌第三方，它可能用客户本人的凭证登录，绕过了为第三方接入设计的接口和授权流程。
4. **从辅助到自主**：监管原本设想的是工具辅助人类决策，而 Agent 走向自主决策后，谁是行为主体、谁承担后果，现有框架没有答案。
5. **需要新的授权层**：业界普遍认为，Agent 金融的前提是互操作性、治理和问责，对应到认证、持续风险监控和责任管理。

## 六、竞争暗线：客户关系保卫战

1. **不只是安全**：有分析指出，银行封锁 Agent 也有竞争考量，担心客户关系被 Agent 中介化，自己沦为后台的账户和管道。
2. **入口之争**：当客户习惯让 Agent 比价、决策和下单，银行对客户的直接触达和影响力会被削弱。
3. **收费站的战略意图**：银行把自己定位为 Agent 交易的强制检查站，本质是想保住数据、费用和客户关系的控制权。
4. **类似平台的玩法**：这与大型平台对购物 Agent 设访问门槛、征收费的逻辑一致，掌握账户入口的一方试图向 Agent 收租。
5. **需要客观看待**：安全与竞争动机往往交织，监管在评估这些措施时，既要防范风险，也要防止准入被用来限制竞争。

## 七、监管的方向：从 Mills Review 到关键第三方

1. **Mills Review**：英国金融行为监管局于 7 月发布里程碑评估，判断 AI 到 2030 年将深刻变革零售金融，并提出多项优先建议。
2. **守住监管边界**：建议包括保障并适配监管边界、监测向自主模型的过渡、为 Agent 金融打基础，以及建立 AI 驱动的监管模型。
3. **关键第三方认定**：不受监管的 AI 提供商若重要到其故障可能威胁金融稳定，可被认定为关键第三方服务提供商，纳入额外监管。
4. **责任前置**：监管的思路是让部署 Agent 的机构无法轻易转移责任，同时把原本游离在体系外的 AI 公司纳入监督视野。
5. **与美联储呼应**：从大西洋彼岸的挤兑警告到英国的准入治理，监管正在围绕 Agent 的身份、授权和责任形成趋同的框架。

## 八、四个冷静判断

1. **封锁是暂时的**：在责任和授权规则明确前，封锁是风险最小的选择，但长期完全封闭既不现实，也不符合开放金融的方向。
2. **甩责不是终局**：单方面把风险推给客户的协议，可能在消费者保护和监管审视下面临挑战，难以成为普遍答案。
3. **核心是可验证**：解决问题的关键不是禁止 Agent，而是建立能证明身份、授权和指令范围的技术与制度安排。
4. **准入治理要平衡**：监管既要补上责任真空，也要防止银行借准入门槛垄断入口、抑制 Agent 带来的创新和竞争。

## 九、和本站其他文章的呼应

1. **和当挤兑按秒发生呼应**：那篇讲 Agent 速度对流动性的冲击，这篇讲账户准入和责任，分别对应 Agent 风险的速度维度与授权维度。
2. **和让 Agent 安全地付钱呼应**：逐笔授权、强认证和授权留痕的思路一致，都是在资金动作前确认身份与意愿。
3. **和让模型分清敌我呼应**：分清可信边界、防止越权操作，是模型层与账户层共同面对的安全命题。

## 结语

一家银行愿意把账户开放给谁，过去是一个清晰的问题：要么是客户本人，要么是持牌、可追责的第三方。AI Agent 把这个问题变得模糊——它拿着客户的密码、学着客户的样子操作，却可能在客户不知情时做出超出授权的事，而银行既无法验证，也不愿担责。于是封锁、甩责、建收费站，成了责任真空下的三种本能反应。这场看似技术封锁的博弈，真正要解决的是一个制度问题：在自主软件替人做主的时代，如何重新确认身份、授权和责任。把这三件事讲清楚、落到可核验的授权层上，Agent 才有可能从被挡在门外，变成被有序地请进门。
