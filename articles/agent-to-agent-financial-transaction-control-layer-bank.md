# 给Agent画一个框

**11 月中旬，摩根大通与现代卡、BNY 与微软几乎同时完成 Agent 间金融交易试点，一个做模拟外汇，一个谈美国国债。**

**两个案例的自动化程度不同：一个让 Agent 在授权框内自动执行，一个只让 Agent 谈判、人工保留最终批准。**

**它们却共用同一套底层逻辑：先验证身份和权限，再用预设限额把 Agent 框住，超出即拦截或上报。**

**机构几乎一致地表示，技术搭建相对简单，真正难的是治理规则、责任认定和交易限额。**

**这为前一天银行封锁 Agent 的故事给出了答案：不是拒绝，而是在控制层上把 Agent 有序地请进来。**

## 一、两个几乎同时落地的试点

1. **摩根大通与现代卡**：现代卡的 Agent 与摩根大通 Kinexys 的 Agent 分工协作，完成了模拟外汇兑换和汇款的概念验证。
2. **具体场景**：Agent 检查假想海外实体的账户余额、判断是否存在资金缺口，比较多家银行的外汇报价，再发起兑换和汇款。
3. **BNY 与微软**：双方完成了行业首个用 Agent 谈判美国国债交易的试点，由 BNY 提供控制层，微软财资部门下达交易指令。
4. **时间点接近**：两则消息在 11 月 17 日至 18 日相继披露，都还是试点或概念验证，尚未进入商用。
5. **共同指向**：它们都在回答同一个问题——当 Agent 开始替机构和彼此做交易，怎样才能让这件事可控、可审、可追责。

## 二、摩根大通：在框内自动执行

1. **两个 Agent 的分工**：现代卡 Agent 负责查余额、比汇率、发起请求，Kinexys Agent 负责验证请求方身份和交易权限并执行。
2. **授权控制**：Kinexys Agent 只在允许的范围内自动执行，对超出权限的交易，会请求负责人批准或直接拒绝。
3. **框的设计**：Kinexys 开发了一套框架，把 Agent 限制在预设交易参数内，它不可能做出任何超出这个框的行为。
4. **具体例子**：如果一个 Agent 获准的交易上限是 500 万美元，那么它一旦试图执行超额交易，系统就会拦截。
5. **治理优先**：摩根大通表示技术本身不是最大障碍，更难的是责任认定，以及 Agent 在无人工直接监督下交易带来的风险。

## 三、BNY：只谈判，不执行

1. **ANP 控制层**：BNY 构建了 Agentic Negotiation Protocol，让不同机构的授权 Agent 安全、透明地交换报价和还价。
2. **安全网关接入**：微软的 Agent 收到具体交易指令后，通过安全 Agent 网关接入 ANP，而非直接登录对方系统。
3. **五项前置验证**：BNY 的控制先核查交易对手、证券、规模、结算条款和可用价格，通过后 Agent 才在授权限额内谈判价格。
4. **中央账本比对**：双方达成一致后，条款被独立提交给 ANP 中央账本比对，确认两家机构对条款的理解完全相同。
5. **人工保留决定权**：随后由双方交易员审查并批准，交易通过现有系统执行和记账，Agent 无权代替任何一方执行交易。

## 四、两种设计，同一套底层逻辑

1. **自动化程度有别**：摩根大通方案允许 Agent 在授权框内自动执行，BNY 方案则把执行权牢牢留给人，Agent 只负责谈判。
2. **保守与进取**：BNY 更保守，强调人工对最终动作的控制；摩根大通更进取，用硬限额换取框内的自动化效率。
3. **身份先行**：两者都先确认 Agent 代表谁、有没有权限，再让它进入交易流程。
4. **限额兜底**：两者都用预设参数和授权限额约束 Agent，使越界在技术上无法发生或立即被拦截。
5. **留痕可重建**：两者都完整记录参与方、消息、控制检查和人工决策，让整笔交易事后可以被还原和审计。

## 五、控制层五件套

1. **身份验证**：确认接入的 Agent 及其背后的机构，解决它代表谁的问题，而不是只看密码是否正确。
2. **授权网关**：Agent 通过专门的安全网关和协议接入，而不是拿着客户凭证直接登录，主体和权限清晰可辨。
3. **交易限额**：用预设参数、授权金额和定价区间把 Agent 框住，超出范围的动作无法执行。
4. **人工否决**：在关键环节保留人工批准，或在超权限时自动上报，确保人始终掌握最终决定权。
5. **全程留痕**：中央账本和审计记录固化每一次报价、校验和决策，为责任认定和事后追溯提供证据。

## 六、为什么说治理比技术难

1. **技术相对简单**：多位负责人都提到，搭建 Agent 交易的技术链路并不难，真正耗时的是配套的监管规则和内控机制。
2. **责任要先厘清**：在没有人工直接监督的情况下，一旦交易出错，责任如何在机构、Agent 提供商和数据方之间分配，需要先有答案。
3. **限额需要校准**：给 Agent 设多大的金额、多宽的价格区间，既关系效率也关系风险，需要业务和风控共同校准。
4. **不能绕开现有体系**：交易仍要通过现有系统执行和记账，复用既有的风险和交易处理控制，而不是另建一套不受监管的通道。
5. **商业化因此谨慎**：摩根大通尚未确定商业化时间表，更复杂的多 Agent 测试计划在 2027 年上半年推进，节奏明显由治理而非技术决定。

## 七、监管沙盒同步推进

1. **新加坡的布局**：新加坡金融管理局在 11 月 18 日宣布金融领域 AI 国家使命，其中包括让 AI Agent 安全交易。
2. **Agentic Money Sandbox**：当局设立受控环境，让金融机构在明确限额和保障下，测试 Agent 发起的支付和资金管理。
3. **合成数据支持**：同时提供合成的银行间数据，供开发者构建和测试反诈骗等工具，避免直接动用真实敏感数据。
4. **机构参与**：星展、华侨、渣打和大华等成为启动伙伴，监管沙盒与机构试点形成呼应。
5. **监管思路一致**：无论是机构自建的控制层还是监管设立的沙盒，核心都是先划框、再试错，把 Agent 约束在可问责的范围内。

## 八、和昨天的封锁如何呼应

1. **封锁是第一步**：前一天的故事里，银行因无法验证委托、责任归属不清，选择把第三方 Agent 挡在门外。
2. **受控开放是方向**：今天的试点表明，封锁不是目的，在身份、权限、限额和留痕都到位后，Agent 可以被有序接入。
3. **从凭证登录到协议接入**：关键转变是不再让 Agent 用客户密码登录，而是通过授权网关和控制层，以可识别、可追责的主体身份参与。
4. **责任仍在机构**：无论 Agent 多自主，部署它的机构始终保留问责，人工要么直接批准，要么通过预设框承担责任。
5. **两条线构成完整图景**：把不可控的挡在门外，把可控的请进框里，这正是 Agent 金融准入治理的一体两面。

## 九、四个冷静判断

1. **试点不等于成熟**：目前都是模拟或小规模试点，未披露真实规模和价格，距离大规模商用仍有距离，不能把演示当成能力兑现。
2. **框的质量决定安全**：Agent 越界风险被控制得如何，取决于限额、校验和留痕的设计质量，而不是模型本身有多聪明。
3. **人工不会马上消失**：即便最自动化的方案也保留超框上报，人工在关键节点的否决和问责短期内不可替代。
4. **标准化是下一步**：各家自建协议难以互通，未来需要跨机构的标准，Agent 间交易才能从双边试点走向规模化生态。

## 十、和本站其他文章的呼应

1. **和把 Agent 挡在门外呼应**：那篇讲账户准入和责任真空，这篇讲准入之后如何用控制层安全交易，是同一治理问题的前后两半。
2. **和让 Agent 安全地付钱呼应**：逐笔授权、强认证和限额控制的思路一致，都是在资金动作前确认身份与意愿。
3. **和当挤兑按秒发生呼应**：正因为 Agent 速度极快，前置的硬限额和人工否决才更重要，控制层本身就是抑制高速风险的闸门。

## 结语

让 Agent 变得更聪明，是模型公司的事；让 Agent 不能越界，则是金融机构必须自己解决的事。这两个试点最有价值的地方，不是它们证明了 Agent 能做外汇、能谈国债，而是它们展示了一套不依赖模型自觉的工程化约束：身份要验证、接入走网关、动作有上限、关键人点头、全程可追溯。摩根大通把它形象地叫做画一个框——Agent 在框内可以高度自主，框外则寸步难行。这也解释了为什么所有机构都在说技术不难、治理才难。框画得是否清楚、是否守得住，才是 Agent 金融能不能真正落地的分水岭。

（口径说明：交易机制与控制设计来自 BNY、摩根大通及合作方的官方发布和媒体报道，目前均为试点或概念验证，部分细节依赖企业一方陈述；控制层与银行治理的映射为作者分析，相关标准和商业化路径仍在形成中。）
