# 让Agent安全地付钱

**OpenAI 在 11 月 13 日发布 ChatGPT Wallet，联手 Visa、万事达和美国运通，让 AI Agent 能代用户下单付款，首个要求每笔都做安全验证且不暴露真实卡号的钱包。**

**核心机制是令牌化：支付网络生成带独立卡号、安全码和有效期的替代凭证，Agent 和商家全程看不到真实卡信息。**

**每笔付款前用户要看清商家、商品、总价和卡片，再用生物识别逐笔授权，形成明确的授权记录。**

**Wirex 前一天推出 Navoka，走另一条路：给 Agent 开独立的 IBAN、借记卡和稳定币钱包，让它只碰自己的账户。**

**两条路线都还在早期，一个限量邀请、一个仅美国 Pro 用户，银行真正放手让 Agent 自主支付前，必须先跑通限额、责任和反欺诈。**

## 一、Agent 从帮你挑东西走到替你付钱

1. **能力跃迁**：大模型 Agent 已经能搜索、比价、推荐商品，现在补上了最后一环，直接替用户完成支付。
2. **碰钱是分水岭**：推荐错了最多浪费时间，支付错了就是真金白银的损失，所以支付环节的安全设计比对话能力更关键。
3. **两类玩家同时进场**：一边是大模型厂商联合传统卡组织，一边是稳定币机构给 Agent 独立账户，代表两种不同的资金路径。
4. **银行高度紧张**：这是银行的核心命脉，谁掌握 Agent 支付入口，谁就可能在未来的交换费和客户关系中占据主动。

## 二、令牌化：让 Agent 看不到真实卡号

1. **什么是令牌**：用户授权后，支付网络生成一个支付令牌，它是真实卡的替代凭证，有自己的卡号、安全码和有效期，真实卡号保存在令牌库里。
2. **令牌不是加密**：令牌本身是一串替代号码，即使泄露，也只能在限定的商户、渠道或场景内使用，范围之外就是无效信息。
3. **范围受限**：卡组织的令牌通常绑定特定商户、设备或渠道，在 Agent 场景里相当于把绑定对象从设备换成了 Agent 会话。
4. **成熟技术复用**：这套机制早已用于手机支付和数字钱包，并非为 Agent 新造，银行和卡组织对它的风控和清算都很熟悉。
5. **直接收益**：Agent 拿不到真实卡号，即使被攻击或 App 侧泄露，攻击者也无法把凭证拿去别处盗刷。

## 三、逐笔授权：解决这笔钱谁授权的

1. **强制验证**：每笔订单都要通过 Face ID 或指纹等生物识别，没有一次性授权后长期免确认的口子。
2. **信息透明**：付款前 Agent 必须展示商家、商品、总价和所选卡片，用户在知情下做决定。
3. **授权留痕**：每次批准都生成一条记录，写清用户授权 Agent 买了什么，这是后续拒付、争议和合规举证的关键证据。
4. **权益延续**：符合条件的卡积分和争议保护照旧，用户不会因为让 Agent 付款就失去原有保障。
5. **责任落点**：逐笔授权本质上是在回答这笔钱到底是谁批准的，把 Agent 的自主行为锚定到一个可追责的自然人。

## 四、另一条路：给 Agent 开独立账户

1. **专用账户设计**：Wirex 的 Navoka 给每个 Agent 分配属于它自己的 IBAN、借记卡和稳定币钱包，Agent 从自己的账户付款。
2. **物理隔离**：Agent 完全接触不到用户的个人银行账户、卡或加密钱包，二者资金天然分开。
3. **损失有上限**：用户只把愿意承担的钱充进 Agent 账户，即使 Agent 出错或被骗，最大损失也限于账户余额。
4. **规则与审计**：持有人设定限额，每笔支付都记录对应的管理规则和审批人，方便后续争议处理。
5. **稳定币属性**：账户支持美元、欧元、英镑并可持有稳定币，走的是银行账户加加密资产的混合路线，也带来合规和汇率风险。

## 五、两条路线的本质区别

1. **资金来源不同**：ChatGPT Wallet 挂在用户现有信用卡上，用令牌隔离；Navoka 让 Agent 用独立账户，从源头隔离。
2. **风险边界不同**：令牌化仍在用户主卡额度内，专用账户的损失上限就是充值进去的钱。
3. **授权方式不同**：前者强调逐笔生物识别，后者强调预设规则、限额和审批人记录。
4. **资金轨道不同**：一个走传统卡组织清算轨道，一个混合银行账户和稳定币。
5. **适用场景不同**：令牌化适合日常消费和成熟卡生态，专用账户更适合企业付款、开发者集成和需要硬隔离的高风险场景。

## 六、银行视角：又爱又怕的支付控制权

1. **爱的一面**：令牌化是银行和卡组织自己的成熟技术，Agent 支付仍走现有轨道，银行不被绕过，还能延续交换费和客户关系。
2. **怕的一面**：Agent 是全新的欺诈面，可能被注入、误判或越权，一旦出问题，责任在用户、模型厂商还是银行很难界定。
3. **封锁与接纳并存**：已有银行选择直接封锁 Agent 交易，也有机构积极把 Agent 纳入合规支付框架，行业并未形成统一答案。
4. **限额即风控**：未来的消费限额、类别和时间段委托，本质是把银行授信额度和商户类别管控的成熟思想搬到 Agent 上。
5. **反欺诈要升级**：Agent 交易的行为模式和真人不同，现有风控模型容易误杀合法 Agent 交易，需要建立识别合法 Agent 的新信号。
6. **中国对照**：银联联合多家银行推出智能体银行卡，数字人民币的智能合约能力也在探索，国内走的是更强调持牌和可控的路径。

## 七、四个冷静判断

1. **都还在早期**：ChatGPT Wallet 仅面向美国成年 Pro 用户，Navoka 还是邀请制，谈大规模普及为时过早。
2. **自动委托是未来**：逐笔授权是现在的安全底线，只有限额、责任和反欺诈跑通后，限额内预授权才会真正放开。
3. **令牌不解决决策错误**：它只保证卡号不泄露和范围受限，防不住 Agent 被注入或买错东西，必须和抗注入、人工审批结合。
4. **标准远未定型**：银行、卡组织、大模型厂商和稳定币机构都在抢 Agent 支付入口，责任划分和技术标准还在博弈中。

## 八、和本站其他文章的呼应

1. **和 AI Agent 怎么碰钱呼应**：那篇讲准入路线之争，这篇讲产品落地后令牌化和专用账户的具体机制，是同一议题的延续。
2. **和让模型分清敌我呼应**：LLMON 解决 Agent 不被外部内容带偏，令牌化解决付款时卡号不泄露，一个管住决策、一个管住凭证。
3. **和买 Agent 还是造 Agent 呼应**：无论采购还是自研，支付授权、限额和审计能力都应是 Agent 平台的硬指标。

## 结语

让 Agent 付钱，难点从来不是技术上能不能把钱转出去，而是怎么把人类支付体系里那套授权、限额、留痕和追责，搬到一个会自主决策的软件身上。令牌化的答案是让 Agent 只拿得到范围受限的替代凭证，专用账户的答案是让 Agent 只碰属于它自己的钱，两者都在试图给自主行为加一道可计算的边界。对银行来说，这既是守住支付轨道的机会，也是必须直面的新欺诈面和责任难题。在限额、责任和反欺诈真正跑通之前，逐笔授权、人工把关仍然是不可退让的底线。
