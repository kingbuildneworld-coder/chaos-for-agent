# 强模型要审查用

**Anthropic 11月9日连发两款新模型：Claude Fable 5.2 和 Mythos 5.2，底层权重相同，用途和开放度却分了两档。**

**Fable 5.2 公开可用，主打编程和通用；Mythos 5.2 专攻网络安全，必须通过 Anthropic 验证计划才能用。**

**Mythos 发现的已确认漏洞里，六分之一是其他所有前沿模型都漏掉的；输出速度最高提升三成，价格下调两成，支持百万 token 上下文。**

**新模型能协调上千个智能体、八天从零写出操作系统，模型能力又跨过一道坎。**

**对银行最直接的启示：越强的模型越要分级准入，通用能力放开，高危场景审查后专用。**

## 一、两款模型到底是什么关系

1. **同一套权重，两种配置**：Fable 和 Mythos 底层是同一个大模型，差别在安全护栏和开放范围。Fable 面向公众开放，带安全限制；Mythos 解除了网络安全方面的限制，只给经过审查的组织用。
2. **Fable 5.2 干什么**：面向编程、通用任务，是这一代的公开主力。跑分登顶，号称八天从零造操作系统，还能自主设计电子设备。
3. **Mythos 5.2 干什么**：Anthropic 最强的网络安全工程模型，用来找漏洞、复现漏洞、修复漏洞。
4. **怎么才能用到 Mythos**：不能直接调，必须通过 Anthropic 的网络安全验证计划，被认定为防御关键软件基础设施的机构才能获得。
5. **为什么要分两档**：模型太强，放开了会被用来攻击；但锁起来又浪费能力。Anthropic 的解法是：通用款加护栏公开卖，攻防款审查后给好人用。

## 二、这次升级的硬指标

1. **速度**：输出速度比上一代最高提升 30%，还可以加钱开 Fast 模式再快 2.5 倍。
2. **价格**：降 20%，输入每百万 token 8 美元、输出 40 美元；Fast 模式翻倍到 16 和 80；批处理只要一半。
3. **上下文**：支持 100 万 token 上下文，一次能读完整套代码库或厚厚的业务文档。
4. **网络安全能力**：内部评测里，Mythos 发现的漏洞比上一代 Opus 5.5 多 10.2%，比自家 Mythos 5.1 多 14.4%；一家安全公司实测，它找到的确认漏洞中六分之一，其他所有前沿模型全漏了。
5. **护栏放松**：Fable 5.2 触发安全拦截的请求比 5.1 少了约 55%，其中网络安全类少 60%、生物类少 40%。模型变聪明了，拒绝人也少了。

## 三、为什么"分两档"这个设计值得银行注意

1. **这正是银行该做的模型准入逻辑**：国家金融监督管理总局的指导意见早就把资金交易、信贷审批、风险管理、承保理赔列为高风险 AI 应用，必须经风险管理委员会批准。Anthropic 的做法是同一个思路——通用能力放开，高危能力审查后专用。
2. **银行内部也该分档**：写邮件、查制度、整理会议纪要这类低风险场景，模型放开用；核心系统代码审计、交易风控、反欺诈这些高危场景，模型要走准入、留痕、双人复核。
3. **网络安全能力是双刃剑**：Mythos 能发现别人漏的漏洞，这对银行是好事——银行自己的核心系统、网银、移动 App 可以用它做代码审计和渗透测试；但同样的能力也在攻击者手里，银行要假设对手也在用强模型找漏洞。
4. **不能迷信模型自带的护栏**：Fable 5.2 拦截率下降了 55%，说明厂商为了好用在放松安全默认。银行把模型接进生产环境，不能指望厂商的默认安全策略，必须在自己这一层加风控、加审批、加熔断。
5. **千 Agent 协同的意义**：新模型能协调上千个智能体。银行早就有多个部门、多个系统、多套流程，一个能统揽的 Agent 编排底座，比单个聪明模型更值钱。

## 四、银行选型时该怎么判断

1. **别只看跑分，看开放门槛**：一个模型强不强，要看它最危险的能力给不给你用、怎么给。需要验证计划才能用的能力，恰恰是银行最该争取和接入的。
2. **算成本账**：降价两成、提速三成、百万上下文，意味着以前不敢用大模型处理的大文档、长日志、全量代码，现在经济性成立了。
3. **押注架构，不押模型**：距离 Anthropic CEO 公开呼吁放慢 AI 开发才两个月，就又发布更强模型。模型迭代太快，银行不能把业务绑死在某一家模型上，要做成可替换的模型路由层。
4. **建自己的高风险清单**：哪些场景必须用审查后的专用模型，哪些可以用公开模型，要有制度、有审批、有记录。
5. **预留攻防升级预算**：攻击者用强模型，防守也要用强模型。银行的安全团队应该尽早申请接入这类经审查的攻防模型，而不是等出事。

## 五、三个冷静判断

1. **"六分之一漏洞别人漏了"是厂商和客户的一方说法**：具体测试范围、漏洞库规模、对比对象没有完全公开，银行真要用，得自己拿核心系统代码做实测。
2. **分两档不等于安全**：Mythos 给审查过的机构用，但审查标准、访问审计、滥用追溯谁来监督，还在早期。银行采购时要把这些写进合同。
3. **护栏放松是趋势也是风险**：模型为了体验少拒绝，意味着幻觉和越权请求更可能被直接执行。银行越是深度用，越要在应用层兜住。

## 六、和本站其他文章的呼应

1. **和金融监管总局指导意见呼应**：高风险应用须经风险管理委员会批准，这和 Anthropic 的"审查后专用"是同一个逻辑——强模型不能裸奔进生产。
2. **和 OCC 银行 AI 定级呼应**：OCC 把自主支付 Agent 列为最高风险层。Mythos 这种攻防专用模型，就该对应银行最高等级的审批和监控。
3. **和 TPU 芯片分场景呼应**：谷歌把芯片按训练、推理、机密、长上下文分工，Anthropic 把模型按通用、网络安全分档——都是能力越强、越要按场景分级，而不是一把梭。

## 结语

Anthropic 这次发的不只是两个更强的模型，而是给行业演示了一套成熟的做法：能力按场景分档，高危能力审查后开放，通用能力带护栏公开。对银行来说，这比跑分更值得抄作业——真正的问题不是"哪个模型最强"，而是"哪个模型、在哪个场景、经过谁的批准、被谁监控"。模型越聪明，银行的准入清单就越要写清楚。
