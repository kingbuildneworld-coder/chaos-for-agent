# 买Agent还是造Agent

**IBM 与微软在 11 月 10 日联合推出 Imagine Enterprise，预置 6000 多个 Agent 和资产，金融服务、保险、零售是首批行业框架。**

**几乎同时，土耳其 Fibabanka 自研的自主 Agent NEO 在自有数据中心上岗，能规划任务、跨系统执行，每一步都有人工审批和审计留痕。**

**这两条新闻正好代表银行落地 Agent 的两条路线：向大厂采购预置平台，还是自己动手造数字员工。**

**数量不等于价值，6000 个 Agent 是营销口径，真正决定成败的是能否接进核心系统、可治理、可问责。**

**对银行而言，自研与采购不是二选一，核心环节自主可控、通用场景借力平台，再用统一治理层收口，是更现实的选择。**

## 一、两条新闻，一个卖平台，一个造员工

1. **平台侧**：IBM 与微软联合发布 Imagine Enterprise，把 IBM 咨询沉淀的 6000 多个 Agent 和资产，架在微软 Foundry、Copilot Studio 之上，主打让企业跳出 AI 试点、规模化部署，内置治理和控制能力。
2. **银行侧**：Fibabanka 由自己的技术团队开发出自主 Agent NEO，职位头衔就叫 AI Agent，运行在本行数据中心，承担常规重复工作，2026 年 11 月正式上岗。
3. **一个共同信号**：无论卖平台还是造员工，行业都在把 Agent 从单个演示推向工业化运营，银行的问题不再是要不要用 Agent，而是怎么规模化、怎么管。

## 二、Imagine Enterprise 的 6000 个 Agent 到底是什么

1. **构成**：这 6000 多个是 IBM 咨询在实际项目中积累的 Agent 和资产，加上行业框架，首批覆盖金融服务、保险、零售，后续再扩展到制造、能源、公共部门和出行。
2. **交付方式**：不是开箱即用的软件，而是由 IBM 咨询主导部署，结合两家公司的技术和企业自身情况落地，本质是平台加咨询服务。
3. **银行蓝图**：IBM 专门给出银行和金融市场蓝图，强调先建企业数据底座，再做多 Agent 编排，最后搭运营控制层，让 CRO、CFO、COO 等高管实时看到流动性、资本、异常和 Agent 行为。
4. **标杆客户要打折扣**：管理约 2 万亿美元资产的 SEI 是合作方，但官方明确这是探索性合作，目前没有量化的生产成果，也没有最终部署，属于共同探索而非已验证成功。

## 三、Fibabanka NEO 这个数字员工怎么干活

1. **能力范围**：NEO 能做任务规划、应用自动化、企业系统集成、文档分析和报告，和只会回答问题的聊天机器人不同，它能把多步骤任务拆开并执行。
2. **工作方式**：员工通过内部通讯渠道派活，NEO 像人一样操作电脑、打开应用、浏览页面，在不同企业系统之间完成流程。
3. **私有化部署**：它完全运行在银行自己数据中心的服务器上，数据不出域，这是受监管机构最看重的一点。
4. **安全边界**：NEO 只通过安全连接访问被授权的系统，在设定权限内行动，而且每一步都有人工审批和审计记录，不是放任自主。
5. **目标**：把员工从重复、低价值的工作中解放出来，去做更需要判断和创造的事。

## 四、两条路线的本质对比

1. **采购路线的优势**：起步快、有现成资产、治理框架内置，不必从零造轮子，适合资源和技术团队有限的机构。
2. **采购路线的风险**：容易被单一平台和咨询商锁定，定制化和深度集成仍要靠外部，6000 个 Agent 里真正贴合本行流程的可能只是少数。
3. **自研路线的优势**：私有部署、数据不出域、权限和审计完全可控，能深度对接核心系统，能力沉淀在自己手里。
4. **自研路线的门槛**：需要过硬的技术团队，周期长、前期投入大，治理和运维体系也要自己搭，中小机构难以承担。
5. **一个容易被忽略的事实**：很多预置 Agent 本质是流程自动化和 RPA 的升级，并非真正的自主智能，采购时要分清是规则自动化还是具备规划和判断能力的 Agent。

## 五、银行视角：治理层才是胜负手

1. **两条路线殊途同归**：IBM 蓝图里的运营控制层，和 Fibabanka 的每步审批加审计，解决的是同一个问题——Agent 规模化后，谁能看见它在做什么、谁为它的动作负责。
2. **对应监管要求**：金融监管对 AI 坚持谁使用谁负责、自主可控，Agent 越多，越需要统一的身份、权限、留痕和问责机制，而不是让每个部门各建各的。
3. **可观测要前置**：Agent 上线前就要能监控它调用了哪些系统、改了哪些数据、在哪一步失败，像管员工一样管 Agent 的上岗、考核和停用。
4. **高危动作必须人在回路**：涉及资金、授信、客户权益的动作，人工审批点不能省，自主程度要和风险等级匹配，而不是追求百分之百自动。

## 六、真正的硬骨头是数据和集成

1. **模型不是瓶颈**：两个案例都说明，Agent 答得好不好、能不能干活，取决于背后的企业知识、数据质量和系统接口，而不是模型参数本身。
2. **数据底座先行**：IBM 把企业数据编织放在第一步，正是因为 Agent 接不通干净、可信的数据，再多预置资产也是空中楼阁。
3. **流程梳理绕不开**：自动化一个混乱流程，只会更快地产生混乱，银行在派 Agent 之前，先要把流程本身标准化、把规则讲清楚。
4. **组织要跟着变**：数字员工接手重复工作后，岗位设计、人机分工、绩效口径都要调整，否则 Agent 会变成无人负责的新系统。

## 七、三个冷静判断

1. **都还是早期信号**：Imagine Enterprise 刚发布、SEI 仅在探索，NEO 是单家银行且未披露具体成效，不宜把发布和上岗直接等同于成熟落地。
2. **私有化是受监管银行的现实选择**：数据不出域、每步审批留痕，决定了银行在核心场景不会轻易把 Agent 完全放到公有平台。
3. **混合路线最务实**：用平台做通用底座和标准化场景，用自研守住核心系统和风控环节，再用一套统一治理层把所有 Agent 管起来，兼顾速度和可控。

## 八、和本站其他文章的呼应

1. **和强模型要审查用呼应**：这篇讲的是 Agent 成规模后的治理，准入审查和运营监控是同一套控制体系的前后两端。
2. **和在 AI 里认领门面呼应**：一篇讲对外的 AI 门面，一篇讲对内的数字员工，银行同时要管好客户侧和内部侧的 Agent。
3. **和 AI 自己做研究呼应**：自主系统能力越强，越要保留人工评审和可复现机制，NEO 的每步审批正是这个原则在生产环境的体现。

## 结语

6000 个预置 Agent 和一个自研数字员工，看似是两条路，其实在提醒银行同一件事：Agent 工业化的浪潮已经到了，但决定差距的不是谁拥有的 Agent 数量多，而是谁先把数据底座、系统接口和治理控制层打扎实。买还是造，没有标准答案——核心能力要握在自己手里，通用能力可以借力，治理必须统一。把 Agent 当成需要管理的员工而不是炫技的玩具，银行才能真正接住这一轮自动化。
