# 别只听模型自证

**微软在 Ignite 大会上发起 AI 透明度倡议，提出一个尖锐判断：模型对自己的描述不是独立证据。**

**企业能看到模型接触的几乎一切，却看不到模型内部发生了什么，这种嵌套黑箱不可接受。**

**倡议联合 40 多家组织，目标是让 AI 系统可问责、可独立验证、设计即安全，且不绑定具体厂商。**

**可信执行环境、零知识证明、加密证明链和签名审计日志，正在让不开黑箱也能验证模型成为可能。**

**对银行而言，这意味着信任的基础从收下厂商承诺，转向能被自己的合规工具独立重放的证据链。**

## 一、Ignite 上的一句话点破了什么

1. **一句关键表述**：微软负责人表示，我们今天能看到模型接触的几乎一切，但看不到模型内部发生了什么，而模型对自己的描述并不是独立证据。
2. **判断的锋芒**：这句话否定了一种常见做法——把模型厂商出具的安全说明、模型卡或问卷，直接当作模型可信的证据。
3. **信任的缺口**：企业可以观察到模型周围的输入输出，却无法重建从请求到结果之间究竟发生了什么，也就难以独立核验模型行为。
4. **倡议的定位**：微软联合 40 多家组织发起 AI 透明度倡议，试图用开放标准填补这个缺口，而不是让企业在创新和安全之间二选一。
5. **问题的普遍性**：参与方包括咨询、软件、审计、支付和汽车等行业，说明这不是某一家厂商的诉求，而是所有大规模部署 AI 的机构共同面对的治理难题。

## 二、什么是嵌套黑箱

1. **第一层黑箱**：模型本身是黑箱，参数规模庞大，企业无法像审查传统模型那样直接读懂它的决策逻辑。
2. **第二层黑箱**：当 Agent 调用多个模型、工具和外部数据时，一个结果背后可能嵌套着多段不可见的处理，黑箱套着黑箱。
3. **看不见的环节**：模型在哪一步调用了外部数据、是否被提示注入影响、是否偏离了授权范围，往往无法事后还原。
4. **传统审计失灵**：传统模型风险管理依赖拿到模型、数据和代码做独立验证，而大模型多以第三方服务形式提供，银行拿不到权重和内部过程。
5. **风险不会因此消失**：银行仍要对模型输出的结果负责，责任没有因为看不懂内部而减轻，反而要求新的验证方式。

## 三、为什么模型自证不能当证据

1. **自证缺乏独立性**：由模型或厂商自己提供的安全声明，本质上是被审计对象的陈述，而不是独立第三方取得的证据。
2. **陈述可能被操纵**：模型可以在测试场景表现良好，在真实环境中行为不同；一份静态说明无法保证持续合规。
3. **结论难以复现**：问卷和审计报告依赖评估者的方法和主观判断，换一个审计方可能得出不同结论，不满足确定性要求。
4. **时点抽样的局限**：一次性的评测只能证明某个时点的状态，无法覆盖模型持续运行、版本更新和 Agent 长期自主行动的全过程。
5. **审计逻辑的基本要求**：审计的核心是独立获取证据，而不是接受被审计对象的口头保证，这一点对 AI 同样适用。

## 四、透明度倡议的三个部分

1. **对接国家标准机构**：微软扩大参与 NIST 的 AI Agent 标准倡议，借助其研究主导制定开放的、全行业的透明度、安全和治理标准。
2. **全生态协同**：与 40 多家组织合作，开发让 AI 系统可问责、可独立验证、设计即安全的开放标准，无论底层模型或供应商是谁。
3. **融入产品与平台**：把标准嵌入自家模型、Foundry 和 Copilot，让客户能把产生的证据用在自己的安全和合规工具上，包括非微软厂商的工具。
4. **关键在证据可消费**：重点不是多发布一份报告，而是让验证结果以结构化、机器可读的方式，进入企业既有的合规工作流。
5. **标准仍在形成中**：目前倡议处于标准制定和试点阶段，最终的开放标准和互操作能力还需要时间和更多机构参与。

## 五、不靠自证靠什么：四类独立验证技术

1. **可信执行环境**：把审计代码、审计数据和模型权重加载进受硬件保护的飞地中运行，再发布把结果绑定到确切代码、数据和模型哈希上的加密证明，即使模型商和审计方互不信任也能保护各自的机密。
2. **零知识证明**：模型商发布数据集和权重的加密承诺，用零知识证明证明承诺确实来自训练过程，可在不暴露模型和数据的情况下完成版权、合规和反事实等审计。
3. **加密证明链**：用持续生成、确定性可重放的证明链替代自证和时点抽样，把每一次治理动作固定下来，使合规状态可被持续验证。
4. **签名审计日志**：用哈希链完整性、数字签名和机器可读的清单记录 Agent 会话，任何一方都能离线验证每个动作都被记录、未被篡改且来自特定加密身份。
5. **共同的思路**：这些技术都不要求打开黑箱或公开模型权重，而是通过密码学手段，让模型的关键属性和行为可被独立证明。

## 六、证据链的三个特征

1. **独立可验证**：监管方或审计方可以下载证明链，在自己的基础设施上运行验证器，无需访问被审计机构的系统就能确认结果。
2. **确定性可重放**：合规验证器对同一份证据会得出相同结论，不依赖评估者的主观判断，满足监管、保险和司法对证据可复现性的要求。
3. **持续而非一次性**：证据在系统运行中持续生成，覆盖模型更新和 Agent 长期行动，而不是只在评审时提供一份静态快照。
4. **选择性披露**：通过哈希和 Merkle 证明，可以只证明某个事件存在而不暴露其他敏感内容，兼顾审计与隐私。
5. **外部锚定**：借助时间戳和透明度服务把证据锚定到外部，防止事后篡改或选择性记录，增强证明的可信度。

## 七、银行模型风险管理遇到的新问题

1. **从自有模型到第三方服务**：银行越来越多通过 API 使用外部大模型，传统可直接验证的模型风险管理方法难以直接套用。
2. **责任与能力的错位**：银行对模型结果承担合规责任，却缺乏直接检视模型内部的能力，必须用独立证据补上这道缺口。
3. **Agent 放大验证难度**：当 Agent 自主调用多个系统并执行资金动作时，验证对象从单个模型扩展到整条行动链路。
4. **供应商集中度风险**：过度依赖少数模型供应商会带来集中度和锁定问题，跨厂商的可比证据是银行管理供应链风险的前提。
5. **需要更新验证工具箱**：银行的模型验证团队需要理解密码学证明、飞地认证等新机制，把它们纳入既有的三道防线和审计流程。

## 八、和监管要求如何呼应

1. **谁使用谁负责**：监管明确金融机构对 AI 应用结果负责，而要真正负起责任，独立验证能力不可或缺。
2. **自主可控与供应链安全**：指导意见要求在外部合作中开展全面风险评估，关注外包、数据安全和集中度，可核验的证据正是供应链治理的抓手。
3. **标准层面的协同**：NIST 的 Agent 标准倡议把 Agent 身份认证、互操作协议和安全控制作为重点，与机构侧的证据基础设施相互衔接。
4. **高风险场景的准入**：对面向公众或高风险的 AI 应用，监管要求建立人工监督和紧急停用机制，这些控制的有效运行也需要证据支撑。
5. **监管可独立核验是方向**：理想状态是监管无需进入机构内部，仅凭可重放的证明链即可确认治理是否持续到位。

## 九、与打开黑箱路线的区别

1. **理解路线**：机制可解释性试图打开黑箱、看清模型内部的计算结构，是研究者从内部理解模型的路径。
2. **证明路线**：本文讲的证据与认证不要求理解内部，而是通过密码学从外部验证模型行为，是治理者和审计者的路径。
3. **两者并不互斥**：理解内部有助于改进模型，外部证明则解决大规模、跨厂商、强保密场景下的可信验证问题。
4. **各自的边界**：可解释性在超大模型上仍面临扩展性难题，而证明机制也存在计算开销和标准未统一的问题。
5. **务实的组合**：对受监管机构而言，更现实的是两条腿走路，用外部证据解决当下的合规验证，同时关注内部可解释性的进展。

## 十、四个冷静判断

1. **倡议不等于标准落地**：目前仍是发起和制定阶段，开放标准能否真正跨厂商互操作，还要看后续推广和验证效果。
2. **技术开销真实存在**：飞地和零知识证明会带来额外计算成本，部分方案开销明显，需要在安全、效率和成本之间权衡。
3. **证据质量取决于工程**：证明链再严密，也依赖底层数据采集和控制设计的完整性，技术本身不能替代治理判断。
4. **独立验证尚处早期**：监管侧完全独立、可在生产环境运行的验证能力还未成熟，当前更多是方向和试点而非现成答案。

## 十一、和本站其他文章的呼应

1. **和看懂 AI 就安全吗呼应**：那篇讲内部理解路线及其未被证实的假设，这篇讲外部证明路线，共同构成 AI 可信验证的两条路径。
2. **和给 Agent 画一个框呼应**：框内的限额和留痕解决越界问题，证据链则让这些控制的运行可被独立验证，是同一治理体系的不同环节。
3. **和把 Agent 挡在门外呼应**：准入阶段需要识别主体和责任，进入之后则需要持续证据，二者共同支撑 Agent 的全生命周期治理。

## 结语

让一个系统可信，最忌讳的做法是只听它如何评价自己。微软这次倡议真正有价值的地方，不是又成立了一个联盟，而是把一个朴素的审计原则重新摆到台面上：独立证据优先于一方陈述。模型厂商的安全说明可以作为线索，但不能作为结论；真正能让银行放心的，是一套不依赖模型自觉、能被独立下载、验证和重放的证据链。可信执行环境、零知识证明和签名日志等技术，正在把"看不懂内部却要承担责任"这个看似无解的困境，逐步变成可工程化的问题。当然，标准还在形成，开销仍然存在，独立验证远未成熟。但方向已经明确：未来的 AI 信任，不会建立在一句"我们很安全"上，而会建立在任何人都能复核的证据之上。
