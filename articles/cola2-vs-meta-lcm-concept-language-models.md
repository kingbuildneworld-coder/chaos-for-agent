# 先想意思再写字：Cola2 与 Meta LCM 深度对比

## 一句话看懂

今天的大模型几乎都是「一个 token 接一个 token」地写。Meta 的 **Large Concept Model（LCM）** 和字节跳动 Seed 的 **Cola2** 都在尝试另一条路：**先在连续的「语义空间」里决定要说什么，再把它翻译成字**。

两者的根本分歧在于：**这个语义空间是借来的，还是自己学的？** LCM 直接用了现成、冻结的句向量空间；Cola2 则让压缩器和生成器一起训练、互相适应。差不多所有其他差异，都从这一点长出来。

---

## 一、基本信息

| | Meta LCM | ByteDance Cola2 |
|---|---|---|
| 论文 | arXiv 2412.08821（2024 年 12 月） | arXiv 2610.31305（2026 年 10 月 22 日） |
| 「概念」是什么 | 一个句子 | 动态切分的语义片段 |
| 语义空间 | 现成的 SONAR 句向量（1024 维），冻结 | 自己训练的动态压缩 VAE |
| 生成方式 | 逐句自回归；最优版本为双塔扩散 | 逐块自回归；块内用扩散 Transformer（DiT），Flow Matching |
| 从向量到文字 | 冻结的 SONAR 解码器 | 与编码器联合训练的掩码扩散解码器 |
| 最大规模 | 7B，约 2.7T token | 约 9B（其中 DiT 约 4B），346.03B 源 token |
| 开源 | 训练代码公开 | 权重和推理代码公开，训练代码未公开 |

---

## 二、Meta LCM：借一个现成的「思想空间」

LCM 的出发点很哲学：人写作时是先想「这一段要表达什么意思」，而不是先想下一个字。为了验证可行性，Meta 做了一个很强的简化：**一个概念 = 一个句子**，并直接使用已有的 SONAR 句向量空间。

**SONAR 的底子很厚**：支持 200 种语言的文本和 57 种语言的语音，用机器翻译、去噪自编码和向量层 MSE 联合训练。所以同一句话的中文版和英文版，大致落在同一个点上。

**流水线**：
1. 用 SaT 分句器切句，单句上限 200 字符（论文发现超过 250 字符的句子重建质量明显下降）。
2. 每句编码成一个 1024 维向量。
3. LCM 在向量序列上做「预测下一句」。
4. SONAR 解码器把预测出的向量还原成句子。

**试过的变体**：直接 MSE 回归（Base-LCM）、单塔和双塔扩散、量化 SONAR 空间（Quant-LCM）。最后双塔扩散被扩到 7B。先在 1.6B 规模、约 1.3T token 上做消融。

**成绩**（指令微调后的 7B 版）：

| 任务 | Two-Tower-7B-IT | Llama-3.1-8B-IT |
|---|---:|---:|
| CNN/DailyMail Rouge-L | 36.47 | 34.97 |
| XSum Rouge-L | 23.71 | 20.35 |
| CNN/DM 流畅度（CoLA 分类器） | 0.767 | 0.973 |
| XSum 流畅度（CoLA 分类器） | 0.683 | 0.941 |

要点是：**内容覆盖更好，文字更不自然**。（注意：这里的 CoLA 是语法可接受性评测，和 Cola2 没有关系。）

**最亮眼的是多语言零样本**：LCM 只用英文训练，却能在 XLSum 的 42 种语言上做摘要，并与 Llama-3.1-8B-IT 比较。这完全是「借来的空间」带来的红利。

**短板也来自同一个地方**：
- SONAR 是为翻译和检索设计的，不是为生成。生成的向量稍稍偏离「合法区域」，解码出来就可能语病；论文专门研究了向量的「脆弱性」。
- 句子是一个很粗的硬编码粒度，长短句表达的信息量差别很大。
- 存储成本高：1 TB 原始文本编码后需要 15–20 TB。
- 生成器无法反过来调整空间本身。

## 三、Cola2：自己学一个「为生成而生」的空间

Cola2 的论文一开头就点出了 LCM 路线的关键问题：分层生成的效果，**取决于潜空间压缩了什么，以及离散生成器怎么用它**。它的答案是让两边「共同适应」（co-adaptive）。

**三个部件**：
1. **动态压缩 VAE**：按内容把文本切成语义片段，每段压成一个紧凑的连续向量。压缩率用一个「无辅助损失的负反馈」机制控制，而不是加一项率损失。
2. **块因果 DiT（约 4B）**：用 Flow Matching 逐块生成潜向量。
3. **块因果掩码扩散解码器**：把潜向量还原成 token，并有潜向量反馈。

**四个关键设计**：
- **重建 + 生成双监督**：潜向量不仅要能还原原文，还要对预测后文有用。
- **梯度单向流动**：token 预测的梯度通过潜向量回传给编码器（让空间「为生成服务」）；但 DiT 先验学习用 stop-gradient 和表征学习解耦，避免两边互相带偏。
- **用干净、加噪、丢弃三种潜条件训练解码器**，再用无分类器引导（CFG）在「忠实还原」和「自主生成」之间调节。发布版的解码器 CFG 为 −0.9，DiT CFG 为 10，8 步 Euler 采样。
- **推理时重新编码**：每写完一块，就按固定片段布局把已生成的文字重新编码，让连续历史和实际文字保持一致。这一步直接针对了 LCM 式「向量越走越偏」的问题。

**成绩**（346.03B 源 token，仍未收敛；每项为三次采样均值）：

| 任务 | Cola2 | Llama-3-8B | LLaDA-8B | Qwen3-8B-Base |
|---|---:|---:|---:|---:|
| 预训练 token | 346B | 15T+ | 2.3T | ~36T |
| HellaSwag | 41.75 | 39.21 | 69.65 | 68.13 |
| StoryCloze | 80.42 | 79.49 | 95.94 | 97.44 |
| ARC-Easy | 87.62 | 90.86 | 93.85 | 97.35 |
| MMLU | 51.32 | 63.19 | 61.27 | 72.31 |
| TruthfulQA | 54.10 | 63.04 | 64.87 | 72.58 |
| **8 项平均** | **60.10** | **66.25** | **72.11** | **75.87** |

Cola2 用不到 Llama-3-8B 三十分之一的数据，在 HellaSwag 和 StoryCloze 上小胜；但在 MMLU、TruthfulQA 这类知识型任务上明显落后。作者自己也强调：各模型配方、分词和计数口径不同，这张表是「背景参考」，不是范式之争的结论。

更有分量的是受控实验：在约 210B token、同等规模和数据下对比自回归、LLaDA、无压缩版 Cola-MDM 和 Cola2-MDM。结果很坦白：**不压缩的版本扩展性最好，压缩版收敛更慢**，只是在约 150B token 之后持续缩小与 LLaDA 的差距，且尚未饱和。

## 四、五个维度的正面对比

### 1. 空间：借来的 vs 自己长的
这是最根本的差别。LCM 的空间早在训练前就定了，模型只能学「在这个空间里怎么走」。Cola2 的空间是被生成任务「塑形」的：压缩了什么、丢弃了什么，由「是否有助于预测后文」决定。代价是失去了 SONAR 自带的跨语言对齐。

### 2. 粒度：句子 vs 语义片段
LCM 把「句子」硬定为单位，需要外部分句器和长度上限；Cola2 动态切分，信息密的地方切得细，冗余的地方切得粗，压缩率由反馈机制稳住。

### 3. 解码：冻结翻译器 vs 共同训练的生成器
LCM 的解码器只会「忠实还原」，输入向量稍有偏差就会出怪句——这很可能是它流畅度偏低的主因（我的推断）。Cola2 的解码器学过如何对待干净、加噪甚至缺失的潜向量，允许自己「补全」，并可用 CFG 调节忠实程度。

### 4. 评测口径：生成任务 vs 基座能力
LCM 主要在摘要和摘要扩写这类长文本生成上评测；Cola2 在阅读理解、常识、知识问答等八项基座任务上评测。两者的数字**不能直接对比**，谁也没有在对方的主场上测过。

### 5. 可用性：可以训 vs 可以跑
LCM 公开了训练代码和 SONAR，适合研究者复现和改造；Cola2 公开了 9B 权重和推理、评测脚本，可以直接跑，但拿不到官方训练配方。两者都是基座研究模型，都不适合直接用于产品。

---

## 五、为什么这条路值得关注

- **数据效率**：如果「先想再写」能用更少数据学到语言的高层结构，就是对「数据墙」的一种回应。Cola2 在两项任务上的小胜是初步信号，不是结论。
- **长程连贯**：在句子或片段层面做规划，理论上更容易维持长文结构；LCM 在摘要上的 Rouge-L 优势与此一致。
- **生成速度**：一块一块走、块内并行，意味着串行步数大幅减少。不过两篇论文都未把延迟优势作为主要卖点。
- **跨模态**：LCM 借 SONAR 天然支持语音；Cola2 的「把视频生成的扩散方法搬到语言」路线，则让文字和图像、视频共用同一类生成器。

---

## 六、需要保持的警惕

- **都是自报结果**。Cola2 论文尚为预印本，原始随机种子未公开；由于潜生成从高斯噪声开始，即使贪心解码，输出也不确定。
- **「省数据」要打折看**。Cola2 的 346B 是「源 token」，与其他模型的计数口径不同；受控实验也显示压缩版本身收敛更慢。
- **知识型能力仍是短板**。MMLU 51.32、TruthfulQA 54.10，明显低于同级自回归模型。
- **LCM 的流畅度问题未解决**。Rouge-L 更高但可读性更差，对写作类应用是硬伤。
- **两者未在同一基准上正面交手**。本文的对比是方法层面的，不是性能排名。

## 结语

LCM 证明了「在概念空间里写作」是可行的，也暴露了用一个现成空间做生成的代价；Cola2 的回答是：**空间不该是预设的，而应该和写作者一起成长**。如果把两者看成一条演进线，下一个值得期待的问题是：能否既自己学空间，又保留 SONAR 那样的跨语言、跨模态对齐？
